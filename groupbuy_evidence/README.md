# 团长端签收凭证与售后防伪系统(纯 Dart 核心)

面向社区团购场景的离线优先防伪证据引擎。团长在仓库门口弱网/无网环境下
用手机完成接货、分拣、自提核销,平台事后能凭密码学证据区分**团长作假**、
**运输丢件**与**正常履约**。

## 1. 要解决的两类作弊

| 作弊手法 | 业务表象 | 本系统的拦截点 |
| --- | --- | --- |
| 幽灵签收后私下转卖 | 没送到的订单被点成已签收,再报缺货 | 签收事件必须带**拍摄瞬间入链的照片哈希**;仓库出库单是独立外部锚点,台账里有签收而仓库无出库 → 裁决 `ghostSignoff` |
| 伪造居民售后骗退款 | 团长冒充居民发起售后 | 售后必须带**居民授权码**(离线 HOTP 可验、一次性、绑定金额),且退款只能原路退回**居民本人支付账户**;团长单方无法构造有效申请,钱也到不了团长手里 |

## 2. 四个硬约束与对应设计

### 2.1 仓库门口信号差 → 离线优先

所有证据操作**先落本地、后补传**,全程不阻塞于网络:

- 本地 JSONL 追加写台账(`JsonlLedgerStorage`,带缓冲的 IOSink,扫描几百件
  不会反复开关文件);
- 每条事件含设备 HMAC 签名,联网后批量上传,服务器独立重放;
- 取货码/售后码都是 **HOTP 派生**,团长手机无网也能本地核验,老人不需要
  联网、不需要装 App,只需念短信里的 6 位数字。

### 2.2 几百件商品要快 → 密码学开销压到微秒级

实测(见 `bin/demo.dart` 场景 4,Mac 端数值,手机量级相近):

```
300 件签名+哈希链写入总耗时: 26 ms,单件约 88 µs
服务器重放校验 300 条: 9 ms
```

单件操作 = 1 次 SHA-256 + 1 次 HMAC + 1 次缓冲写。真实瓶颈在相机成像,
不在证据引擎。扫码 UI 设计为"扫码即走",事件在后台入链。

### 2.3 居民多是老人 → 零学习成本的确认方式

- 居民侧:收短信/语音电话得到 6 位数字,自提时报给团长即可;
- 团长侧:输入数字,App 离线显示通过/不通过;
- 容错通道:确实拿不到码时允许"无码核销",但**必须填写原因**(真实 App 中
  还要第二人见证工号),该事件在裁决时证据力弱于扫码核销,居民投诉时由
  团长承担责任;
- 防暴力破解:每单 5 次错误即锁定,需联网重新签发,比较采用恒定时间算法。

### 2.4 平台要分清责任 → 可解释的裁决矩阵

裁决引擎(`AdjudicationEngine`)是规则引擎而非黑盒评分,每个结论都附带
具体证据行,便于申诉与稽核:

| 证据组合 | 裁决 | 责任方 |
| --- | --- | --- |
| 设备有签收,仓库出库单无此单 | `ghostSignoff` 幽灵签收 | 团长(欺诈) |
| 售后无服务器侧居民授权 / 退款目标非居民账户 / 无授权码哈希 | `fraudulentAftersale` 虚假售后 | 团长(欺诈) |
| 仓库已发、设备无签收且有交接阶段异常 | `transportLoss` 运输丢件 | 运输/仓库 |
| 已签收已分拣,无任何闭环事件,居民未取货 | `leaderResponsibleLoss` 团长责任丢失 | 团长(保管责任) |
| 设备显示码核验通过但居民否认取货 | `pickupDispute` 取货争议 | 人工复核(码外泄/设备问题) |
| 台账哈希链或签名校验失败 | `chainTampered` 台账篡改 | 团长(最高优先级调查) |
| 居民授权码有效、退款退回居民账户 | `legitimateAftersale` 正常售后 | 平台正常赔付 |

团长风险分聚合后触发 `normal / watch / suspend / investigate` 四级处置
(出现一次幽灵签收即自动暂停签收权限转稽核)。

## 3. 信任机制细节

### 3.1 哈希链 + 设备签名

```
genesisHash
   └─ ev0: body0 → selfHash0 = SHA256(canonical(body0)), sig0 = HMAC(deviceKey, body0)
        └─ ev1: body1(prevHash=selfHash0) → selfHash1, sig1
             └─ ev2: ...
```

- 规范化 JSON(键排序、无空白、UTC 时间)保证设备与服务器对同一字节序列
  做哈希/签名;
- 改任意一条旧事件 → 该条 selfHash 对不上;重算哈希 → 没有设备密钥,
  签名对不上;删事件 → seq 与 prevHash 同时断裂;
- 服务器定期下发**检查点**(对链头的服务器签名),团长连整条链一起重写也
  绕不过服务器保存的检查点。

### 3.2 防倒签的可信时间

- 在线时获取服务器签名时间锚 `TimeAnchor(serverTime, monotonicAtIssue)`;
- 离线时时间 = `锚点服务器时间 +(设备单调时钟增量)`。用户手动改系统时钟
  只影响墙上时钟,**单调时钟不可改**,因此无法把事件时间往前拨;
- 超过 12 小时外推窗口的事件标记为低可信,仍记录但进入稽核视野;
- 全新设备从未联网时产生的事件显式标记 `anchored=false`,服务器要求补锚
  后才接受其权利主张。

### 3.3 照片即拍即锚

- 相机回调时立即对原始字节算 SHA-256 并写入签名事件,事后补传照片;
- 相册选图无法替换:字节哈希与事件内哈希不一致即拒;
- `PhotoRegistry` 禁止同一张照片绑定两个订单(同图重复报损是转卖掩盖的
  典型特征);
- 服务端图像取证(重复图检测、JPEG 重编码痕迹、EXIF 与事件时间比对)是
  第二层,不影响离线链路。

### 3.4 售后授权码

派生消息绑定 `域标签 || counter || 金额(分) || orderId`:

- 域标签使取货码与售后码不可互换;
- 金额入码 → 20 元的码不能授权 200 元退款;
- orderId 入码 → A 单的码不能贴到 B 单;
- 一次性:核验通过后 `markUsed`,重放返回 `alreadyUsed`;
- 短期有效,过期离线即拒;
- 台账只存码的加盐哈希,不存明文。

## 4. 模块结构

```
lib/
  groupbuy_evidence.dart        公共导出
  src/
    canonical_json.dart         确定性 JSON 编码(哈希/签名的统一输入)
    clock.dart                  服务器锚定可信时钟,防手动改时间
    signer.dart                 签名抽象 + HMAC-SHA256 实现(可换 Ed25519)
    event.dart                  事件类型、必填字段约束、事件模型
    storage.dart                持久化接缝:内存 / JSONL 追加文件
    ledger.dart                 哈希链台账 + 独立重放校验 + 检查点
    photo.dart                  拍照取证与照片-订单绑定/防重放
    pickup_code.dart            HOTP 取货码、离线核验、暴力破解锁定
    aftersale.dart              居民售后授权码:金额绑定、一次性、过期
    adjudication.dart           责任裁决引擎与团长风险分级
    workflow.dart               Flutter UI 唯一入口:工作流编排服务
bin/demo.dart                   四个场景的端到端演示
test/                           50 个测试,覆盖全部裁决路径与篡改手法
```

## 5. Flutter 集成方式

本包是纯 Dart(仅依赖 `crypto`),可直接被 Flutter app 依赖。落地时的
平台适配点:

1. **设备密钥**:`HmacEvidenceSigner` 的 secret 在团长注册激活时由服务端
   下发,存入 iOS Keychain / Android Keystore(推荐进一步换成 Keystore 内
   非对称 Ed25519 密钥,服务端只存公钥,后端被拖库也无法伪造设备事件);
2. **相机**:用 `camera` 插件直接拿图像流,在 `takePicture` 回调里调用
   `PhotoRegistry.fromBytes`,不经过相册;EXIF 位置作为辅助字段;
3. **单调时钟**:Flutter 侧用 `Stopwatch` 启动值或原生 `SystemClock.
   elapsedRealtime()` / `CACurrentMediaTime()` 桥接;
4. **持久化**:生产实现替换 `JsonlLedgerStorage` 为 sqflite 表(同样保持
   追加语义),或写应用沙箱文件并配合系统备份排除;
5. **同步**:后台 Worker 消费 `pendingSync()`,带指数退避;服务端 ACK 后
   `markSynced`;每次同步成功拉取新检查点;
6. **短信/语音码下发**在服务端完成,设备通过最后一次在线同步拿到的
   counter 清单离线核验。

## 7. 已知边界(需要产品/运营配合的部分)

- 证据系统能证明"团长设备签了什么、何时签、照片是否原始",但无法物理
  阻止团长对着空箱子拍照——这由仓库出库独立锚点 + 同图检测 + 异常率
  运营规则兜底;
- 居民主动把取货码告诉团长代为确认属于社会工程风险,`pickupDispute`
  保留人工复核通道,不自动处罚;
- 根权限设备可编辑本地文件,但无法伪造服务器检查点与设备密钥签名,
  篡改只会让整条链校验失败(`chainTampered`),直接进入最高级调查;
- HMAC 方案信任服务端持密;最高安全等级应迁移到非对称签名(接口已预留)。
